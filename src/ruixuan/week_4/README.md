1. 性能数据在代码文件顶部 ：作者把每个 kernel 的实测性能数据以注释形式贴在源码开头。
2. 结果因平台而异，"反直觉"是正常的 ：同一份代码在不同 GPU 架构（V100/A100/4090）和不同 nvcc 版本下表现不同。比如某个"优化版"reduce 在你的 4090 上可能反而比 baseline 慢——这不代表代码错了，而是硬件差异（SM 数量、缓存大小、调度器行为、编译器优化决策都不同）。
3. 正确姿势是"只探索、只 debug 现象，不背结论" ：不要把这些数据当标准答案记，而应该拿自己机器上的实测结果去分析"为什么快/为什么慢"，这才是学 CUDA 性能优化的意义。
对你的实际影响：你在 4090 D 上跑这些教程代码时，如果结果和文件顶部注释的数据（大概率是作者用 V100/A100 测的）对不上，甚至出现"越优化越慢"，属于预期内现象，不用怀疑自己环境配错了。
